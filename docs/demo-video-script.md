# 시연 영상 대본과 촬영 순서

작성 2026-11-11 · 상태: 초안, 팀 검토 전 · 촬영 예정 11-13

## 한눈에

| 항목 | 내용 |
| --- | --- |
| 길이 | 2분 26초 (기획서 7절의 2분 30초 안) |
| 한 문장 | 잘하는지가 아니라, 달라졌는지를 본다 |
| 구성 | 걱정(연출) → 주행 → 주차 후 카드 → 주간 카드 → 가족 요약 → 운전 점수와의 차이 → 구현 범위 |
| 화면 | 앱 화면은 모두 실제 녹화. 도입과 마무리의 사람 장면만 힉스필드로 만든 연출 컷 |

공모전 가이드에는 시연 영상의 길이·형식·제출 방법 규정이 없다(2026-11-11에 [지원·제출 방법](https://appdevchallenge.auto-hmg.io/guide/submission)을 읽음). "목업 · 프로토타입 · 화면 녹화 인정"이라고만 적혀 있다. AI로 만든 장면에 대한 규정도 없다. 그래서 아래 원칙은 우리가 정한 것이다.

지킬 것 다섯 가지:

1. **앱 화면은 만들어 내지 않는다.** 차 화면과 폰 화면은 실제로 돌아가는 것을 녹화한다. 힉스필드 컷에는 화면 내용이 보이지 않게 한다.
2. **연출 컷에는 `연출 영상 · AI 생성`이라고 표기한다.**
3. **시연용 값에는 표기를 붙인다.** 구간 8초, 합성 평소 기록, 에뮬레이터.
4. **만들지 않은 기능을 동작하는 것처럼 보여 주지 않는다.** 운전 약속과 편한 길 안내는 마지막에 "다음 단계"라고 말로만 언급한다.
5. **소리를 끄고 봐도 이해되게 한다.** 내레이션 전체를 자막으로 넣는다.

컷 단위의 화면·움직임·글자·소리는 [컷별 컨셉 시트](demo-video-concept-sheets.md)에 있다. 컨셉 시트는 맨 앞에 3초짜리 콜드 오픈을 넣고 마지막 장면을 세 컷으로 나누는 안을 담고 있고, 채택하면 이 대본의 시간표를 그쪽에 맞춘다.

## 기획서 시나리오와 다른 점

기획서 7절과 화면 기획 6절의 순서를, 지금 실제로 도는 것에 맞춰 줄였다.

| 기획서 장면 | 영상에서 | 이유 |
| --- | --- | --- |
| 자녀가 초대 → 부모님이 차에서 동의 | 부모님이 차에서 코드를 띄움 → 자녀가 입력 | 구현이 이 방향이다. 화면 기획 7절의 1번 제안과 같다 |
| 깜빡이 놓침, 재탐색 2회 | 강한 제동, 조향 보정 | 내비 재탐색 신호는 받아 보지 못했다. 제동과 조향은 에뮬레이터에서 확인했다 |
| 불편했던 곳 표시, 빠른 길 / 편한 길 | 넣지 않음 | 구현하지 않았다 |
| 밤 9시 시동 인사, 다른 방법으로 가기 | 넣지 않음 | 구현하지 않았다 |
| 주간 리포트 → 자녀 폰 요약 | 그대로 | 구현했고 에뮬레이터에서 확인했다 |

## 장면표 (편집 순서)

내레이션은 모두 490음절쯤이고, 1초에 3~5음절로 읽으면 시간에 맞는다. 존댓말, 짧은 문장으로 읽는다. 등장인물 이름은 가상의 이름이다(어머니 김정숙, 딸 민지).

### 1. 걱정 · 0:00–0:12

- **화면**: 힉스필드 컷 H1(어머니가 운전하는 옆모습) → H2(딸이 휴대폰을 내려다보는 모습)
- **내레이션**: 일흔둘 어머니는 오늘도 직접 운전해서 병원에 가십니다. 괜찮으시냐고 물으면 답은 늘 같습니다. "괜찮다."
- **자막**: `연출 영상 · AI 생성`

### 2. 한 줄 정의 · 0:12–0:24

- **화면**: 제목 카드 `DriveWatch · 부모님 운전에 차는 스마트워치` → 랜딩 첫 화면(<https://drive.olvend.com/>)의 "한 번의 이동에서 일어나는 일"
- **내레이션**: DriveWatch는 부모님 운전에 차는 스마트워치입니다. 나이로 판단하지 않습니다. 본인의 평소와 비교해서, 달라졌을 때만 알려 드립니다.

### 3. 주행 · 0:24–0:50

- **화면**: 왼쪽에 Virtual Console(차속, 브레이크가 움직임), 오른쪽에 에뮬레이터의 차량 화면. 48초 주행을 2배속으로 24초에 보여 준다.
- **내레이션**: 기어를 D단에 넣으면 기록이 시작됩니다. 차속과 브레이크, 조향 신호를 차에서 직접 받습니다. 주행 중에는 내비가 화면 앞에 있고, DriveWatch는 뒤에서 신호만 받습니다. 운전하는 동안에는 아무것도 묻지 않습니다.
- **자막**: `Pleos Connect 에뮬레이터 · 실차 아님` `시연 모드 · 구간 8초(제품은 2분) · 평소 기록은 합성` `2배속` `기어·브레이크·조향: Pleos Vehicle SDK · 차속: AAOS Car API`
- **편집**: 강한 제동이 많은 4번째 구간(출발 후 24–32초)과 5번째 구간(32–40초)에 화면 표시를 넣는다. 2배속이면 장면 안에서 12초와 16초 지점이다. 내레이션을 이 지점에 맞추지 않아도 되게 숫자는 장면 4에서 말한다.

### 4. 주차 후 카드 · 0:50–1:08

- **화면**: P단에 넣으면 카드가 뜬다. 카드 문구를 2초 이상 멈춰 보여 준 뒤 구간 막대로 넘어간다.
- **화면에 나오는 문구**: `평소와 달라요` · `강한 제동 · 8초 구간당 평소 3회 이하, 이번 최고 5회`
- **내레이션**: 주차하면 카드 한 장이 뜹니다. "평소와 달라요." 강한 제동이 평소에는 세 번 이하였는데, 오늘은 다섯 번이었습니다. 점수를 매기지 않습니다. 어느 구간에서 달랐는지를 보여 드립니다.

### 5. 주간 카드 · 1:08–1:32

- **화면**: 날짜가 넘어가는 표시(`2주 뒤` → `4주 뒤`)와 함께, 지난 12주 띠가 안정에서 관찰로, 관찰에서 대화 권장으로 바뀐다. 근거 한 줄을 확대한다. 장면 4의 주행은 하루의 일이고 이 장면은 여러 주에 걸친 일이라, 날짜 표시가 없으면 한 번의 주행으로 "대화 권장"이 된 것처럼 보인다.
- **화면에 나오는 문구**: `강한 제동이 2주째 평소보다 많았어요` → `강한 제동이 4주째, 조향 보정이 2주째 평소보다 많았어요` · `강한 제동 · 100km당 6.3회 → 21.9회 · 4주 연속`
- **내레이션**: 하루 달랐다고 가족에게 알리지 않습니다. 같은 변화가 2주 이어지면 "관찰", 4주 이어지면 "대화 권장"이 됩니다. 이 카드는 부모님이 먼저 봅니다.
- **자막**: `시연용 합성 기록 12주`

### 6. 가족 요약 · 1:32–2:02

- **화면**: ① 차 화면에 초대 코드 → ② 실제 휴대폰에서 코드 입력 → ③ 차에서 `가족에게 보내기` → ④ 휴대폰에 요약 도착(대화 권장, 달라진 점, 숫자 근거) → ⑤ `확인했어요` → ⑥ 차 화면에 "민지 확인"
- **내레이션**: 가족 연결은 부모님이 차에서 코드를 띄우면서 시작됩니다. 요약은 부모님이 "가족에게 보내기"를 눌러야 갑니다. 위치와 경로는 보내지 않습니다. 달라진 점을 보내고, 숫자 근거는 부모님이 허락했을 때만 보냅니다. 자녀가 확인하면 차에서도 보입니다.
- **편집**: 여섯 단계를 30초에 넣으니 단계마다 4~5초다. 폰 화면은 4초마다 새로 고쳐지므로 ③ 뒤에 요약이 뜰 때까지 기다리는 시간은 자른다. 차 화면과 폰 화면을 나란히 두면 오가는 것이 한눈에 보인다.

### 7. 운전 점수와 다른 점 · 2:02–2:12

- **화면**: 랜딩의 "잘하는지가 아니라, 달라졌는지를 봐요" 부분
- **내레이션**: 운전 점수는 얼마나 잘하는지를 매깁니다. DriveWatch는 어제의 나와 비교해서, 달라졌는지를 봅니다.

### 8. 마무리 · 2:12–2:26

- **화면**: 랜딩의 "어디까지 만들었나" → 힉스필드 컷 H3(모녀가 식탁에서 이야기하는 모습) → 제목 카드와 주소(`drive.olvend.com`, GitHub 저장소 주소)
- **내레이션**: 판정과 신호 수집, 가족 요약은 Pleos 에뮬레이터에서 동작합니다. 운전 약속과 편한 길 안내가 다음 단계입니다. DriveWatch.
- **자막**: H3에 `연출 영상 · AI 생성`

## 어느 화면을 찍나

제품 화면(팀원 작업)이 에뮬레이터에서 돌면 그것을 찍고, 아니면 지금 있는 것으로 찍는다. **11-12 저녁에 정한다.**

| 장면 | 1순위: 제품 화면 | 대체: 지금 있는 것 |
| --- | --- | --- |
| 3 주행 | 홈(C5) → 주행 | 확인용 앱. 구간마다 강한 제동 횟수가 실시간으로 올라간다 |
| 4 주차 후 카드 | 도착(C9) | 확인용 앱의 카드. 같은 문구가 나온다. 또는 웹 시연 `console.html`의 차량 센터 화면 |
| 5 주간 카드 | 주간 카드(C10), 12주 기록(C11) | 웹 시연 `console.html`의 `12주 재생` |
| 6 가족 요약 | 초대 코드(C4), 주간 카드의 보내기(C10) | 확인용 앱의 `가족 등록·코드`, `요약 보내기 (시연용)`, `가족 확인 보기` |
| 6 폰 화면 | 실제 휴대폰의 <https://drive.olvend.com/family/> | 같음 |

- 대체 화면으로 찍으면 확인용 앱은 글자만 있는 화면이다. 자막 `동작 확인용 화면`을 붙이고, 카드 문구는 편집에서 크게 다시 보여 준다.
- 웹 시연을 차 화면처럼 보여 줄 때는 자막 `웹 시연`을 붙인다. 웹의 Pleos 화면은 예시 신호 재생이고, 에뮬레이터 화면과 섞어서 같은 것처럼 보이게 하지 않는다.
- 제품 화면은 `drivewatch-core`의 `Cards`와 `drivewatch-vehicle`의 `DriveCollectorService`, `FamilyLink`를 쓰면 위와 같은 문구와 숫자가 나온다.

## 촬영 순서

편집 순서와 다르다. 준비가 같은 것끼리 묶었다.

### 전날 (11-12) 확인

촬영을 깨뜨릴 수 있는데 아직 확인하지 않은 것들이다.

- [ ] 에뮬레이터 앱에서 공개 주소(https)로 요약이 가는지. 지금까지는 개발 PC의 서버(http)로만 확인했다.
- [ ] 실제 휴대폰에서 폰 화면이 제대로 보이는지. 휴대폰으로 열어 본 적이 없다.
- [ ] 화면 녹화 방법. 에뮬레이터 창과 브라우저를 나란히 놓고 macOS 화면 기록(Cmd+Shift+5)으로 찍는 것을 기본으로 한다. `adb shell screenrecord`는 이 이미지에서 해 보지 않았다.
- [ ] 휴대폰 화면 녹화가 켜지는지, 알림이 꺼져 있는지.

공개 주소로 가지 않으면 개발 PC의 서버를 쓴다(이 방법도 휴대폰으로는 해 보지 않았다). 휴대폰을 같은 Wi-Fi에 두고 `HOST=0.0.0.0 npm start`로 켠 뒤, 앱은 `http://10.0.2.2:8795`로, 휴대폰은 `http://<PC 주소>:8795/family/`로 연다.

### 세션 A · 에뮬레이터 (장면 3, 4, 6의 차 화면)

```sh
~/Library/Android/sdk/emulator/emulator -avd Pleos_Connect_v2.1      # 창이 보이게 켠다
adb forward tcp:8088 tcp:8088                                        # Virtual Console: http://127.0.0.1:8088/
adb shell pm clear com.drivewatch.harness                            # 새 차로 시작 (확인용 앱으로 찍을 때)
adb shell am start -n com.drivewatch.harness/.MainActivity
```

1. 권한 두 개를 허용한다. 이 부분은 영상에 넣지 않는다.
2. **주행 (장면 3, 4)**: 녹화를 시작하고 `node tools/vconsole-demo.js`를 실행한다. 48초 뒤 P단에 들어가고 카드가 뜬다. 카드가 뜬 뒤 5초 더 찍는다. 매번 같은 주행이라 여러 번 찍어도 결과가 같다.
3. **가족 (장면 6)**: 세션 B와 같이 찍는다. 초대 코드는 10분 동안 한 번만 쓸 수 있다.

### 세션 B · 휴대폰 (장면 6)

차 화면과 휴대폰을 동시에 녹화한다. 순서를 지킨다.

1. 휴대폰에서 폰 화면을 열고 가입한다(이름 `민지`). 가입은 영상에 넣지 않아도 된다.
2. 차: `가족 등록·코드` → 코드가 뜬다.
3. 휴대폰: 코드 입력, 호칭 선택 → 연결 완료.
4. 차: `요약 보내기`. **한 번만 누른다.** 같은 주에 다시 보내면 휴대폰의 확인 표시가 지워진다.
5. 휴대폰: 요약이 뜨면 천천히 내려 보고 `확인했어요`.
6. 차: `가족 확인 보기` → "민지"가 보인다.

끝나면 공개 서버에 시연 기록이 남는다. 지우는 기능이 없어서, 지우려면 [family-server의 배포 절](../family-server/README.md)대로 기록 파일을 비우고 서비스를 다시 켠다.

### 세션 C · 웹 (장면 2, 5, 7, 8)

브라우저 창 크기를 16:9로 맞추고 주소 표시줄이 보이게 찍는다.

1. <https://drive.olvend.com/> 첫 화면: 9초 개요가 한 번 도는 것을 찍는다.
2. `console.html`: `12주 재생`을 눌러 띠가 바뀌는 것을 찍는다(장면 5를 웹으로 찍을 때).
3. 랜딩을 내려 "잘하는지가 아니라, 달라졌는지를 봐요"와 "어디까지 만들었나"를 찍는다.

### 세션 D · 힉스필드 컷

| 컷 | 길이 | 쓰는 곳 | 내용 |
| --- | --- | --- | --- |
| H1 | 5초 | 장면 1 | 70대 한국인 여성이 낮에 승용차를 운전한다. 조수석 쪽에서 본 옆모습, 두 손은 운전대, 차분한 표정, 창밖으로 주택가가 지나간다 |

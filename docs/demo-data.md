# 시연 데이터와 시연 이벤트

작성 2026-11-10 · 상태: 방향 합의, 일부 미정

## 원칙

가짜는 신호가 들어오는 입구에만 둔다. 그 뒤(수집 → 판정 → 화면)는 실제 코드로 돈다. 가짜인 부분은 화면에 "시연용"이라고 표기한다.

| 필요한 것 | 방법 | 상태 |
| --- | --- | --- |
| 과거 기록 | 시연 프로필에 합성 기록을 심는다. 실제 프로필은 "학습 중"부터 시작한다 | 합성 기록은 `drivewatch-core`의 `demo/`에 있음 |
| 이번 주행 | 차량 신호를 실제로 받고, 시연 모드에서 구간 길이만 2분에서 8초로 줄인다 | 구현, 에뮬레이터에서 확인 (`drivewatch-vehicle`) |
| 신호 입구 교체 | 평소에는 차량 신호, 필요하면 녹화한 신호를 같은 입구로 흘린다 | 구현, 에뮬레이터에서 확인 (`ReplaySignalSource`) |
| 시간 건너뛰기 | 앱 전체가 하나의 시계를 보고, 시연 패널이 그 시계만 옮긴다 | 미구현 |

## 정한 것

- **합성 기록의 날짜는 오늘 기준이다.** `DemoWeeklyHistory.firstMondayFor(today, completedWeeks)`로 시작일을 잡는다. `completedWeeks = 8`이면 평소 8주만 과거가 되어 "안정"에서 시작하고, 시계를 4주 넘기면 "대화 권장"이 된다. 요일이 달라도 결과가 같은지 테스트한다.
- **첫 주행 장면은 제동·조향으로 보여준다.** 화면 기획 6절의 2번 장면("깜빡이 놓침, 재탐색 2회")은 내비 재탐색 신호를 아직 받아 보지 못해서 지금 구조로는 만들 수 없다. 방향지시등은 받을 수 있지만 "놓쳤다"를 알려면 회전 안내 지점이 필요하다.
- **가족 요약용 서버는 둘 수 있다.** 이 PC를 포함해 어디든 구성할 수 있다.
- **가족 요약 서버는 `drive.olvend.com`에 올렸다.** 폰 화면은 <https://drive.olvend.com/family/>, REST API 명세는 <https://drive.olvend.com/api/docs>다. 형식과 배포 방법은 [family-server](../family-server/README.md)에 있다.
- **자녀 폰 화면은 웹 화면으로 만든다.** 서버가 화면을 내주고, 시연할 때는 실제 휴대폰 브라우저로 연다. 제출하는 APK는 차량 앱 하나다. 푸시 알림은 없고 화면이 주기적으로 새로 고쳐진다.

## 아직 정하지 않은 것

- 이번 주행을 누가 운전하는가: 발표자가 Virtual Console에서 직접, 또는 `node legacy/vconsole-demo.js`로 자동. 스크립트는 같은 주행을 매번 똑같이 재생한다.
- 팀원 프로토타입에 폰 화면이 이미 있다면 그것을 웹으로 옮길지 새로 만들지.

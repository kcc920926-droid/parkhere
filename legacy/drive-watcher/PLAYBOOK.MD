# 드라이브 와쳐 플레이북

드라이브 와쳐는 **같은 운전자가 비슷한 길에서 평소와 달라진 구간을 주차 후에 확인하는 차량용 앱**이다. 운전자는 무엇이 달랐는지, 어느 구간에서 그랬는지, 평소와 얼마나 차이가 났는지를 센터 화면에서 본다. 변화가 여러 주 이어지면 최근 흐름을 돌아보고 다음 이동을 결정할 근거로 쓴다.

[공개 시연](https://drive.olvend.com/) · [차량 센터 화면](console.html) · [판단 엔진](engine-demo.html) · [개인 경향 모델](profile-demo.html)

## 1. 어떤 문제부터 푸나

매주 병원이나 장을 보러 차를 모는 사람이 익숙한 길에서 제동이 유난히 잦았다고 느껴도, 주차하고 나면 어느 구간이었는지 떠올리기 어렵다. 한 번 강하게 제동한 날에는 공사나 끼어들기 같은 이유가 있을 수 있다. 비슷한 조건에서 같은 변화가 이어졌다면 그 구간을 다시 보고 다음에 어떻게 이동할지 생각해 볼 수 있다.

첫 검증 대상은 **비슷한 도심 생활길을 반복하는 운전자**다. 고령 운전자와 먼저 검증하되 비교 기준은 나이대가 아니라 본인의 과거 기록에 둔다. 같은 제동 횟수라도 운전자와 도로 조건에 따라 의미가 달라진다는 가설을 검증한다.

## 2. 운전자가 만나는 화면

| 순간 | 센터 화면과 동작 |
| --- | --- |
| **처음 쓰는 날** | 기록에 동의하고 프로필을 선택한다. 비교할 기록이 충분해질 때까지 **“평소 주행을 알아가는 중이에요”**로 표시한다. 이 초기 설정은 제품 설계다. |
| **주행 중** | 내비 화면을 사용한다. 차량 신호를 화면 뒤에서 받아 기록하는 흐름을 목표로 하고, 화면 전환·주행 제한·권한 상태에서도 수신이 가능한지 대상 차량에서 검증한다. |
| **주차하고 앱 열기** | 변화가 확인되면 **“평소와 달라요”** 카드에 신호 하나와 비교값을 보여준다. 도심 예시에서는 **2분 구간당 평소 기준 3회 이하, 이번 최고 5회**가 먼저 보인다. 기록이 부족하면 그 상태를 표시한다. |
| **어느 구간이었나요?** | 해당 구간과 구간별 값이 열린다. 같은 예시에서는 **출발 후 6–8분에 4회, 8–10분에 5회**가 가상 경로에 표시된다. 분할 화면에서는 왼쪽 내비와 오른쪽 상세를 함께 보고, 창을 바꿔도 보던 상세가 이어진다. |
| **이번 주 돌아보기** | **이번 주 카드**에서 변화가 돌아왔는지 이어졌는지 본다. 제동이 한 주만 늘어난 경우와 여러 주 동안 제동·조향 변화가 겹친 경우를 다르게 보여준다. |

주차 후 카드는 짧은 제목, 근거 한 줄, 상세 버튼 하나를 기본으로 한다. 상세 화면은 차종별 앱 영역과 `CarUxRestrictions`를 확인해 연다. 주행 중 실시간 배너는 공모전용 시뮬레이터에 있는 표현이며, 차량에서 어떤 알림을 제공할지는 별도로 검증한다. [Pleos 화면 구조](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/app-structure-screen-model) · [Pleos 주행 규제](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy)

## 3. 무엇을 비교하고 언제 알려주나

| 질문 | 현재 MVP에서 답하는 방식 | 제품에서 확인할 것 |
| --- | --- | --- |
| **이번 주행의 어디가 달랐나** | 같은 도로 조건의 개인 기준선과 구간별 제동·조향·누적 주행 시간을 비교한다. 같은 신호가 두 구간 연속 상한을 넘으면 처음 감지한 시점과 근거를 남긴다. | 정체·공사·낯선 길을 어떻게 구별할지, 센서 공백과 비교 자료 부족을 어떻게 표시할지 확인한다. |
| **최근에도 계속 달라졌나** | 주행 요약을 주별로 모아 **학습 중 / 자료 부족 / 안정 / 관찰 / 대화 권장**을 계산한다. 예시에서는 같은 지표가 2주 이어지면 관찰, 한 지표가 4주 이어지거나 두 지표가 각각 2주 이어지면 대화 권장이 된다. | 지표마다 필요한 주행량과 경계값을 정한다. 공유는 운전자가 필요할 때 선택하는 제품 가설로 둔다. |
| **여러 습관이 함께 달라졌나** | 연구용 화면에서 반응 시간, 차간 시간, 최소 차간거리, 제동 길이, 가속 비율, 속도 변화가 함께 움직이는 방식을 운전자별 오토인코더로 학습한다. 오늘과 모델이 예상한 값의 차이를 보여준다. | 동일 운전자의 실제 기록으로 먼저 단순한 개인 기준선과 비교한다. 오류 사례와 변화 이유를 설명할 수 있는지 확인한 뒤 차량 화면 적용을 결정한다. |

주차 요약에는 구간 비교 규칙을 사용한다. 주간 카드는 별도의 합성 기록으로 장기 흐름을 시연하고, 개인 경향 모델의 점수는 주차 요약이나 주간 카드의 판정에 들어가지 않는다. **관측된 변화**를 기록하고, 음주·졸음·인지 저하 등 원인은 그에 맞는 별도 근거가 확보될 때 다룬다. [구간 판정](engine.js) · [주간 판정](weekly.js) · [개인 경향 모델](profile-model.js)

## 4. 공모전에서 보여줄 순서

1. **차량 센터 화면부터 연다.** 내비 → 주차 → 드라이브 와쳐 → 구간 상세를 따라가고 분할 화면으로 바꾼다. 실제 사용자가 어떤 결정을 더 쉽게 할지 설명한다.
2. **판단이 입력에 따라 바뀌는 걸 보여준다.** 같은 코스에서 직접 운전하고 센터 화면으로 기록을 보낸다. 한 구간만 기준을 넘긴 기록과 두 구간 연속 넘긴 기록의 카드와 지도 표시를 비교한다.
3. **출처를 바꿔 본다.** Pleos SDK 예시에서 속도·조향·브레이크 신호의 단위와 집계 흐름을 보여준 뒤, 공개 실측 CAN에서는 원본 HTTP 수신 내역과 판정을 확인한다.
4. **지속성과 개인차를 보여준다.** 이번 주 카드에서 단발과 지속 변화를 비교하고, 개인 경향 모델에서 같은 입력을 두 가상 운전자 기준으로 평가한다. 합성 검증에서 잡힌 경우와 놓친 경우도 함께 보여준다.

## 5. 적용 범위와 실차 검증

**첫 제품 범위는 생활길의 변화 확인이다.** 운전자가 부담을 느낀 구간을 주차 후 기억하고 다음 방문 때 다시 확인하는 흐름을 먼저 검증한다. 장거리에서는 누적 주행 시간과 휴식 계획을, 귀가 상황에서는 운전자가 저장한 대체 이동 계획을 연결하는 방향을 검토한다. 우회 경로 추천이나 휴게소 안내는 실제 내비에서 위치·방향·경로를 확인한 뒤 붙인다.

| 단계 | 다음 단계로 넘어갈 근거 |
| --- | --- |
| **웹 MVP** | 조작을 바꾸면 기록과 결과가 바뀌고, 동일 기록을 재생하면 같은 결과가 나온다. 데이터 출처, 감지 근거, 비교 불가 상태를 구분해 보여준다. |
| **Pleos 에뮬레이터** | 속도·변속·제동·조향을 신호별로 확인한다. 수신 권한, 단위, 시각, 갱신 주기, 앱 전환 중 공백을 로그로 남긴다. P 상태와 주행 제한에 따라 요약 화면이 열리는지 검증한다. |
| **실차 기록** | 같은 운전자와 비슷한 경로에서 여러 날 기록을 모은다. 정체나 끼어들기가 있었던 날을 포함해 관찰 결과를 따로 표시하고, 오탐·미탐·판정 보류 비율을 운전자와 경로별로 비교한다. |
| **운전자 검증** | 주차 후 도움 없이 변화 구간을 찾는 데 걸린 시간, 카드의 이유를 자기 말로 설명할 수 있는지, 반복해서 돌아보는지를 확인한다. |

웹 시연에서 확인한 건 브라우저 조작과 판정의 연결이다. 공개 CAN은 도로에서 기록한 별도 샘플이며, Pleos 화면은 문서에 맞춘 예시 신호 재생이다. 모델의 합성 데이터 검증 결과를 실차 정확도로 사용하지 않는다. 실차 실험 전에는 운전자별 기록 분리, 수집 범위, 보관 기간, 삭제와 공유 동의 방식을 정한다. [Pleos Virtual Console 가이드](https://document.pleos.ai/en/docs/pleos-only/app-test-guide/virtual-console-guide)

### 차량 센터 화면 시연

[차량 센터 화면](console.html)에서 내비가 표시되는 상태로 시작한다. **주차하기 → 드라이브 와쳐 → 어느 구간이었나요?** 순서로 눌러 본다. 변화 카드는 선택한 기록을 공통 엔진으로 판정해 보여준다. ‘예시 기록’을 고르면 도심 시연 기록을 본다. 출발 후 6–10분에 강한 제동이 평소 기준인 2분당 3회를 두 구간 연속 넘겼고, 상세 화면은 그 구간과 4회·5회 기록을 같은 가상 경로에 표시한다.

판단 엔진에서 **직접 운전**을 시작한다. 8초 구간이 하나 이상 끝나면 **센터 화면에서 내 기록 보기**로 전달할 수 있고, 코스를 완주하면 최신 직접 운전이 브라우저에 저장된다. 같은 브라우저의 센터 화면에서 **내 직접 운전**을 선택한 다음 주차한다. 구간별 제동 횟수와 주행거리를 다시 읽어 판정하고, 제동 위치와 연속 초과 구간을 가상 경로에 표시한다. 아직 완료하지 않은 구간은 전달하지 않는다.

**분할 화면**을 누르면 왼쪽 내비와 오른쪽 앱을 함께 확인할 수 있다. 레이아웃을 바꿔도 요약이나 상세 상태가 이어진다. 실제 차량 연동은 별도 검증이 필요하다. [Pleos 화면 구성](https://document.pleos.ai/docs/connect/guide/docs-design/getting-started/layout)

### 주간 카드

센터 화면에서 **주차하기 → 드라이브 와쳐 → 이번 주 카드**를 누른다. 한 운전자의 도심 주행 12주(주 4회, 8km)를 합성한 기록으로 주별 상태를 보여준다. 화면은 세 층으로 나눴다.

- **차량 화면(운전자가 보는 것)**: 이번 주 상태와 한 문장, 지난 12주 상태 띠, 평소를 넘은 지표만 평소 대 이번 주로 비교한다.
- **발표용 조작(차량 화면 밖)**: 기록 선택, `←`/`→`, **12주 재생**. 재생하면 한 주씩 넘어가며 상태가 바뀐다.
- **엔진 설명(차량 화면 아래)**: 주별 값과 그 주의 평소 상한을 두 지표로 그리고 판정 규칙을 적는다.

| 기록 | 보여줄 것 |
| --- | --- |
| **변화가 이어진 기록** | 첫 2주는 학습 중이다. 10월 12일 주에 강한 제동이 한 번 튀어도 안정이다. 2주 연속이면 관찰, 강한 제동 4주째와 조향 보정 2주째가 겹치는 11월 2일 주에 대화 권장이 된다. |
| **한 주만 달랐던 기록** | 같은 주에 강한 제동이 튀지만 다음 주에 돌아오므로 12주 내내 안정이다. |

주행 중 판정과 같은 방식으로 평소 범위를 정한다. 기준은 직전 8주 중 주행이 3회 이상인 주이며, 상한은 `중앙값 + max(최소 여유, 3 × 중앙절대편차)`다. 제동과 조향은 100km당 횟수로, 쉬지 않고 운전한 시간은 그 주의 최댓값으로 비교한다. 첫 주행부터 14일이 지나고 누적 주행 10회에 도달하기 전에는 학습 상태로 둔다. 주행이 3회보다 적은 주는 판정하지 않고 연속 주 수를 끊는다. 상한을 넘은 주는 다음 기준선에서 뺀다. 기준값과 여유는 시연용 파라미터다. [주간 판정](weekly.js) · [합성 12주](weekly-history.js)

### 개인 경향 모델

[개인 경향 모델](profile-demo.html)은 구간 횟수가 아니라 **운전자의 습관이 함께 움직이는 방식**과 오늘을 비교한다. 습관은 판단 엔진과 같은 48초 코스에서 잰다. 앞차 감속 후 첫 제동까지의 반응 시간, 차간 시간, 앞차 감속 중 가장 가까운 거리, 제동 길이, 가속 페달 비율, 속도 변화의 6개다. 앞차가 감속할 때 가운데 차로에 없으면 반응 시간을 재지 않는다. 3초 안에 제동하지 않으면 3초로 기록한다. [습관 측정](habits.js)

가상 운전자별 평소 80회는 같은 코스를 자동 운전으로 달린 기록이다. 자동 운전은 반응 지연, 선호 차간, 순항 속도, 제동 길이로 움직이고, 주행마다 '기민함'과 '서두름'이 여러 습관을 함께 바꾼다. 이 80회로 6 → 5 → 2 → 5 → 6 오토인코더를 학습한다. 오늘 습관을 가운데 2칸(경향 좌표)으로 압축했다가 복원하며, 복원값은 "이 운전자의 다른 습관으로 보면 이래야 하는 값"이다. 차이가 과거 80회 중 최대 차이의 1.25배를 넘으면 평소 경향과 다르다고 판단한다. 운전자 표준편차 기준 0.75 이상 벗어난 습관을 이유로 보여준다.

| 오늘 | 차분한 운전자 모델의 판단 |
| --- | --- |
| **평소 같은 날** | 경향 안 |
| **서두른 날** | 차간·속도가 달라져도 습관들이 같은 방향으로 함께 움직여 경향 안 |
| **반응이 늦은 날** | 다름 · 첫 이유는 반응 시간 |
| **다른 사람이 운전한 날** | 다름 · 같은 기록이 빠른 운전자 모델에서는 경향 안 |
| **내 직접 운전** | 판단 엔진의 직접 운전을 끝까지 달리면 습관 6개가 이 브라우저에 저장되고, **내 운전 경향 판단 받기**로 넘어온다 |

**자동 검증**은 학습에 쓰지 않은 580일(평소 300일, 반응이 0.05–0.4초 늦은 280일)을 고정 시드로 같은 코스에서 달려 판단한다. 지연 정도별 감지율 곡선을 그리고, 0.1초 이상 늦었는데 놓친 날을 미탐으로 센다. 같은 화면의 학습 설정으로 재계산하면 차분한 운전자는 오탐 1.3%(4/300일), 미탐 62.9%(151/240일)다. 빠른 운전자도 같은 방식으로 검증하면 오탐 5.0%(15/300일), 미탐 36.7%(88/240일)다. 0.4초 늦은 날은 모두 감지하지만 0.1–0.2초 지연은 대부분 놓친다. 틀린 날은 목록에서 눌러 신경망으로 다시 재생한다.

이 580일과 평소 80회는 [미리 달린 결과](profile-cache.js)로 함께 배포해 페이지가 바로 열린다. **브라우저에서 다시 달려 확인**을 누르면 같은 시드로 실시간 재계산한다. 시드나 시뮬레이터를 바꾸면 저장소 루트에서 `node drive-watcher/build-profile-cache.js`로 다시 만든다. `profile-cache.test.js`가 미리 달린 결과와 실시간 주행의 일치를 확인한다.

운전자 성향, 습관 사이의 연결, 코스는 모두 시연용이다. 실제 제품의 습관 지표, 모델 구조, 경계선은 실차 기록과 오탐·미탐 검증으로 다시 정한다. [모델](profile-model.js) · [화면](profile-demo.js)

### 가상 코스 시연

[공모전용 판단 엔진](engine-demo.html)을 연다.

1. **자동 재생**을 누른다. 기준 차량이 첫 두 구간에서 감속하면 자동 입력은 각각 한 번씩 강하게 제동한다. 내 속도선의 제동점과 첫 두 구간의 `1회 → 1회`를 확인한다. 두 번째 구간이 끝나면 **평소와 달라요**가 뜬다. 이후 코스가 이어지는 동안 처음 감지한 구간과 횟수가 남는다.
2. **직접 운전**을 눌러 같은 코스를 시작한다. `W` / `↑`로 가속하고 `S` / `↓`로 제동한다. `A` / `D` 또는 좌우 화살표로 차로 안팎을 움직인다. 가속할 때 엔진음이 커지고 높아지며, ‘엔진음’ 버튼으로 끌 수 있다. 첫 감속에서만 길게 누르고 다음 감속에서는 짧게 눌러본다. 첫 구간만 상한을 넘으면 감지가 성립하지 않는다.

두 모드는 48초 코스, 세 차로의 차량 10대, 차량 모형, 합성 개인 기록을 공유한다. 뒤에서 내려다보는 화면의 민트색 차가 내 차다. 차선 확인 표시에서 중앙과의 거리, 차체가 차선에 걸쳤는지를 볼 수 있다. 그래프의 점선은 감속을 시연하는 기준 차량의 속도다. 키를 오래 누를수록 페달 입력이 커지고 모의 차량의 속도가 달라진다. 페달에 의한 감속이 시연 기준인 4m/s² 이상에 도달하면 한 번의 제동으로 기록한다. 페달을 놓고 입력이 충분히 줄면 다음 제동을 셀 수 있다. 그래프와 감지에 같은 결과를 사용한다.

이 코스는 8초 구간 여섯 개로 시연한다. **평소 5회**는 같은 코스를 짧게 끊어 제동하는 자동 운전으로 실제로 달린 기록이다. 그래프에 옅은 선으로 깔리며, 다섯 번 모두 구간별 강한 제동이 0회라 비교 상한도 0회다(`habits.test.js`가 확인). 구간 길이와 기준값은 이 모의 코스에 적용한다. 실제 차량에서 쓸 값은 별도 검증이 필요하다.

달리는 동안 **실시간 습관** 6개가 갱신된다. 개인 경향 모델에 들어가는 값과 같다. 앞차가 감속하면 도로 위에 "앞차 감속 시작"이 뜨고, 제동하면 "반응 0.97초"처럼 그 자리에서 잰 반응 시간이 뜬다. 다른 차로에 있으면 그 반응은 재지 않는다고 알린다. 변화를 감지하면 도로 화면 테두리가 깜빡이고, 감지 구간을 설명하는 배너가 뜨고, 그래프에 감지 구간이 음영으로 남는다. 자동 재생은 감지 순간을 1.6초 슬로모션으로 보여 준 뒤 남은 구간을 2.5배로 넘긴다. 직접 운전은 실제 속도를 유지한다. 직접 운전을 완주하면 **내 운전 경향 판단 받기**로 개인 경향 모델에 넘어간다.

### Pleos SDK 신호 예시

### 공개 실측 CAN 신호 시연

화면에서 **실측 CAN 수신 → 실측 기록 불러오기 → 4배속 재생**을 누른다. 브라우저가 comma2k19의 공개 예제에서 CAN 차량 속도와 핸들 각도의 시각·값 배열을 받는다. 수신 화면에서 네 원본 URL의 HTTP 상태, 받은 바이트 수와 처리 시간을 확인한다. 재생 시각에 맞춰 원본 값을 표시하고, 속도는 m/s에서 km/h로 변환한다. 조향각은 단위와 값을 확인할 수 있도록 그래프에 표시한다. [comma2k19 데이터 설명](https://github.com/commaai/comma2k19/tree/4c7f1a6e1957745beadc1def0e7225f559b09a2a#dataset-structure)

속도 차이로 계산한 최근 약 0.5초 감속이 4 m/s²에 이르면 이벤트를 센다. 첫 25초에서 5초짜리 비교 구간 다섯 개를 만들고, 이후 완전한 5초 구간의 감속 이벤트를 같은 판정 엔진에 넣는다. 이 기준은 한 기록 안의 비교값이다. 이 화면에서 불러오는 채널은 속도와 조향각이다. 속도로 이동 여부와 감속을 확인하며, 마지막 5초 미만 구간은 판정에서 제외한다. 원본 수신에 인터넷 연결이 필요하다.

Pleos에서 속도는 AAOS `PERF_VEHICLE_SPEED`, 핸들 각도는 Vehicle SDK의 `getCurrentSteeringWheelAngle`이 연결 대상이다. 대상 앱에서 권한과 신호 수신을 확인하는 단계가 남아 있다. [Pleos 속도 조회 안내](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/vehicle-app-faq#클러스터-속도-조회-방법) · [Pleos 핸들 각도 API](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api/steering-wheel/get-current-steering-wheel-angle)

### 도심·고속도로 기록 재생

| 보여줄 것 | 재생 순서 | 화면에서 확인할 것 |
| --- | --- | --- |
| **한 번 튄 신호** | 도심 기록 → 평소 주행 → 재생 | 제동 4회가 개인 상한 3회를 한 구간만 넘는다. 다음 구간이 평소 범위로 돌아오면 변화 기록은 생기지 않는다. |
| **이어지는 변화** | 도심 기록 → 변화가 있던 날 → 재생 | 제동과 조향이 연속 두 구간에서 상한을 넘는다. 처음 감지한 시각, 현재값, 개인 상한이 남는다. P에 도달하면 감지 시점의 비교값을 다시 보여준다. |
| **다른 조건, 같은 규칙** | 고속도로 기록 → 변화가 있던 날 → 재생 | 도로 조건이 바뀌면 기준선이 바뀐다. 제동과 조향은 평소 범위에 있고 누적 주행 시간이 82분, 84분으로 상한 80분을 두 번 넘는다. |

‘도심·고속도로 기록 재생’을 펼치고 ‘다음 구간’을 누르면 관찰 → 변화 기록 → 주차를 끊어서 보여줄 수 있다. 매번 동일한 합성 기록을 재생하므로 발표 중 통신이나 차량에 의존하지 않는다. 대시보드에 들어오는 값은 2분 구간 요약이다. 원시 센서 수집과 구간 집계는 다음 검증 범위다.

### 공통 엔진과 데이터 계약

```text
입력 소스 → 같은 형식의 구간 요약 → 같은 조건의 개인 기준선 → 감지 기록
                                                               ↓
                                        주행 요약 → 주별 집계 → 주별 개인 기준선 → 안정·관찰·대화 권장
```

| 항목 | 계약 |
| --- | --- |
| **운전자** | 엔진 인스턴스 하나에는 한 운전자의 과거 표본과 현재 주행만 넣는다. 구간·주간 시연은 각각 한 명의 예시 기록을 사용한다. 개인 경향 화면은 두 가상 운전자를 바꿔 비교할 수 있다. |
| **구간** | `minute`은 주행 시작 기준 분, `context`는 도심 또는 고속도로, `gear`와 `speedKph`는 구간 끝 상태다. 주행 비교는 D 상태의 이동 기록 또는 변속 신호가 없는 소스에서 속도로 확인한 이동 기록으로 한다. 주차는 P 및 속도 0이 함께 확인될 때 표시한다. |
| **신호** | `values.hardBrakes`와 `values.steeringCorrections`는 해당 2분간 횟수, `values.minutesSinceBreak`는 직전 휴식 이후 누적 주행 분이다. 사용할 수 없는 신호는 생략한다. |
| **평소 범위** | 같은 조건의 유효한 표본 5개 이상에서 신호별 중앙값을 구한다. 상한은 `중앙값 + max(최소 여유, 3 × 중앙절대편차)`다. 최소 여유는 제동·조향 각 2회, 누적 시간 8분이다. 값은 시연용 비교 파라미터다. |
| **연속 조건** | 같은 신호가 연속 2분 구간 두 개에서 상한을 초과하면 해당 주행의 첫 변화로 기록한다. 단발 초과, 비교값 누락, 도로 조건 변경, 구간 공백, 정차는 연속을 끊는다. 평소 자료가 부족한 신호는 비교에서 제외한다. |
| **출력** | `observation`은 비교 상태, `readings`는 비교값과 연속 횟수다. `detection`에는 처음 조건을 충족한 시각, 도로 조건, 해당 신호와 비교 근거를 남긴다. 주차 후에도 같은 근거를 읽을 수 있다. |

엔진에는 장면 이름이나 적용 분야를 전달하지 않는다. [엔진](engine.js)과 [합성 입력](replays.js), [시연 화면](app.js)을 분리했다. 같은 입력 형식으로 Pleos 데이터를 연결할 수 있다. 운전자에게 보여줄 상세 화면은 주차 확인 뒤 여는 정책을 적용한다. 재생 대시보드의 실시간 수치는 발표자가 보는 시뮬레이션이다.

**감지 결과의 의미는 ‘평소와 다른 신호가 이어졌다’까지다.** 연령, 음주, 졸음, 페달 오조작의 원인 판별에는 별도 근거와 검증이 필요하다. 세 분야에 공통으로 재사용하는 것은 변화 기록이며, 제품에서 이를 어떤 정보와 조합할지는 다음 기획 범위다. [NHTSA 음주운전 예방 기술 보고서](https://www.nhtsa.gov/sites/nhtsa.gov/files/2026-03/Report-to-Congress-Advanced-Impaired-Driving-Prevention-Technology.pdf)

| --- | --- |
| **지금 · 웹 재생** | 동일 입력을 반복하면 동일한 시점에 감지한다. 평소 기록과 단발 초과에 감지 결과가 생기지 않는다. 도로 조건이 바뀌거나 신호가 빠지면 연속 초과로 묶지 않는다. 근거가 주차 시점까지 남는다. |
| **다음 · Pleos 에뮬레이터** | Virtual Console에서 변속·제동·조향을 바꿔 실제 테스트 앱의 콜백, 단위, 주기, 지원 권한을 기록한다. 속도와 도로 조건의 출처도 확인한다. 확인한 신호부터 구간 요약으로 만들어 웹 재생과 결과를 대조한다. |
| **이후 · 실제 주행 기록** | 동일 운전자의 여러 날 기록을 같은 조건끼리 비교한다. 교통량이나 도로 굴곡의 영향, 센서 누락, 일상적인 급제동 등으로 생기는 오탐과 놓친 변화를 별도 표본으로 검증한다. 실측에 맞춰 구간 길이와 기준선, 신호 정의를 정한다. |

Pleos Virtual Console은 변속, 브레이크 페달, 조향각 등의 입력을 바꿀 수 있다. 이 항목을 앱에서 받을 수 있는지와 실제 갱신 주기는 대상 앱 로그에서 확인한다. 제동과 조향 횟수의 정의는 이 검증 뒤에 정한다. [Pleos Virtual Console 가이드](https://document.pleos.ai/en/docs/pleos-only/app-test-guide/virtual-console-guide)

한 번은 넘기고,
두 번 이어지면
적어 둬요

주간 카드가 몇 주에 걸친 변화를 본다면, 이 엔진은 주행 하나 안에서 어느 구간이 평소와 달랐는지 찾아요. 이 페이지는 실제 판정 코드를 브라우저에서 그대로 돌려요.

  • 주행을 2분 구간으로 나눠, 같은 종류의 길에서 쌓인 내 기록과 비교해요.
  • 차량 앱에는 아직 넣지 않았어요. 웹과 Kotlin 모듈로 따로 만들어 같은 결과가 나오는지 검증했어요.

같은 길,
두 번 달려 봤어요

평소 같은 날과 달라진 날의 기록을 엔진에 차례로 넣어요. 엔진은 구간마다 본인의 평소 상한과 비교하고, 같은 신호가 두 구간 연속 넘을 때만 변화로 적어요.

준비

출발 전

재생하면 2분 구간을 하나씩 엔진에 넣어요.

합성한 주행 기록이에요. 구간 나누기, 평소 상한, 두 구간 연속 판정은 실제 엔진 코드(engine.js) 그대로예요.

기준은 남이 아니라,
내 지난 주행

모두에게 같은 잣대를 대지 않아요. 같은 종류의 길에서 쌓인 본인 기록의 가운데 값에 여유를 더해 ‘평소 상한’을 잡아요. 기록이 다섯 번 쌓이기 전에는 비교하지 않아요.

들쭉날쭉한 사람은 여유를 더 넉넉하게 잡아요. 여유는 정해 둔 최소 폭과 ‘가운데 값에서 벗어난 정도의 3배’ 가운데 큰 쪽이에요. 최소 폭(강한 제동·조향 2회, 시간 8분)은 가정값이에요.

실제 차 신호로도
돌려 봤어요

합성 기록만이 아니에요. 공개된 실측 주행 기록과 Pleos 에뮬레이터의 차량 신호에도 같은 규칙을 그대로 썼어요.

공개 실측 CAN · comma2k19

실제 주행 1분, 아무 일도 없었어요

실제 차에서 기록한 속도와 조향각을 GitHub의 공개 원본에서 바로 받아 와요. 5초 구간으로 나누고, 앞 25초를 이 주행의 기준으로 써요.

    아직 불러오지 않았어요.

    원본 배열 4개(약 80KB)를 raw.githubusercontent.com에서 받아요. 이 기록에는 기어 신호가 없어 속도로 주행 여부를 판단해요.

    Pleos Connect 에뮬레이터 v2.1.0에서 확인

    다섯 번째 구간에서 감지했어요

    에뮬레이터에서 차속과 브레이크 신호를 실제로 받아 같은 주행을 재생했어요. 엔진은 구간마다 강한 제동을 이렇게 셌어요.

    1. 10–8초
    2. 08–16초
    3. 116–24초
    4. 424–32초
    5. 532–40초
    6. 140–48초

    평소 상한을 넘은 구간이 두 번 이어진 32–40초에 변화로 적었어요.

    시연 모드라 구간이 8초예요. 실차에서 확인한 것은 아니에요.

    검증한 것과
    아직인 것

    이 엔진은 주간 카드 판정과 별개로 만든 연구용이에요. 차량 앱에 붙이기 전에 무엇을 확인했는지 적어 둬요.

    확인했어요

    • 웹과 Kotlin 모듈에 같은 입력을 넣으면 같은 결과가 나와요(테스트)
    • 에뮬레이터에서 같은 주행을 재생하면 같은 시점에 감지해요
    • 평소 기록과 한 번 튄 기록에서는 감지하지 않아요

    가정값이에요

    • 여유 폭(제동·조향 2회, 시간 8분)과 기록 다섯 번
    • 강한 제동 기준 4m/s²
    • 이 페이지의 도심·고속도로 기록(합성)

    아직이에요

    • 차량 앱의 주간 카드에 구간 근거로 붙이기(2차 발표 전)
    • 실차 신호의 주기와 단위, 빠지는 구간 확인
    • 같은 운전자의 여러 날 기록으로 오탐·미탐 재기
    직접 운전해 보기 키보드로 가상 도로를 달리고, Pleos SDK 예시 신호를 재생해 보는 실험 화면이에요. 데스크톱에서 보기 좋아요. 엔진 코드 보기 GitHub에 웹 엔진(drive-watcher/engine.js)과 같은 판정을 옮긴 Kotlin 모듈(drivewatch-core), 테스트가 있어요.

    DriveWatch · 팀 M92 · 현대자동차그룹 차량용 앱 개발 공모전 출품작

    판단 엔진은 연구용 웹 프로토타입이에요. 차량 앱의 주간 판정(본인의 8주 평소 대비 변화)과는 따로 동작해요.

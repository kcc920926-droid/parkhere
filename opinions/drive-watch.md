# DriveWatch (가제) · 부모님 운전 동반자 심층 검토

작성 winter1 · 2026-11-05 (문제 정의·해결 방안·효과·이름 보강) · 상태: **후보 심층 검토, 팀 합의 전**. 평가 기준은 [judging-criteria.md](judging-criteria.md), 다른 후보는 [idea-brainstorm.md](idea-brainstorm.md).

## 1. 문제 정의

### 1.1 규모와 시의성

- **사고는 늘고 있다**: 2025년 고령 운전자 교통사고 45,873건, 전년 대비 8.3% 증가. 65세 이상이 일으킨 사고가 전체의 약 20%, 사고율은 65세 미만의 1.13배.
- **그런데 반납은 하지 않는다**: 서울 고령 운전자 면허 자진 반납률 2.67%, 65~69세는 0.16%. 인센티브는 20~48만원 1회.
- **제도는 아직 답이 없다**: 야간·고속도로 제한 같은 조건부 면허는 2019년부터 검토만 하고 있고, 2026-10에도 "고위험 운전자 고속도로 진입 금지" 검토 보도와 반발이 이어졌다. 전문가들은 나이보다 운전 능력으로 판단해야 한다고 지적한다.

수치는 기사 보도 기준(출처 목록 참고)이며 기준 연도·산출 방식이 다르다. 기획서에는 경찰청·도로교통공단 원자료(TAAS)로 교체한다.

### 1.2 한 문장으로

> 고령 운전자의 운전 능력은 **서서히, 눈에 띄지 않게** 변하는데, 본인·가족·제도 누구도 그 변화를 **객관적으로 알 수단**이 없고, 알게 되더라도 "계속 운전"과 "면허 반납" 사이에 **단계적으로 대응할 선택지**가 없다.

### 1.3 세 가지 구체적 문제

| | 문제 | 지금 실제로 벌어지는 일 | 근거 | 결과 |
| --- | --- | --- | --- | --- |
| **P1** | **변화를 아무도 모른다** | 공식 점검은 75세 이상 3년, 65~74세 5년에 한 번 면허 갱신 때뿐이다. 인지 점검은 치매 선별 수준이라 등급이 낮아도 대부분 통과한다. 본인은 "아직 괜찮다", 가족은 명절에 가끔 동승할 때만 본다. | 도로교통법 갱신 주기·교육 의무 보도, "치매 아니면 패스" 보도 | **사고가 첫 신호가 된다.** |
| **P2** | **가족 대화가 싸움이 된다** | 자녀는 뉴스를 볼 때마다 불안하지만 근거가 없어 "이제 운전 그만하세요"라는 결론부터 꺼낸다. 부모님에게 그 말은 나이로 판단받는 모욕이다. | 인터뷰로 검증 필요(12절) | 말을 안 하거나 갈등만 남는다. |
| **P3** | **선택지가 둘뿐이다** | "계속 운전 / 면허 반납"뿐이다. 반납 인센티브는 20~48만원 1회, 조건부 면허(야간·고속도로 제한)는 2019년부터 검토만 하고 있다. | 반납률 서울 2.67%, 65~69세 0.16% | **대부분 아무 조정 없이 예전처럼 운전**한다. |

### 1.4 기존 수단이 해결하지 못하는 이유

| 기존 수단 | 한계 |
| --- | --- |
| 면허 갱신 시 검사 | 3~5년에 한 번, 시험장의 한 시점. 일상 운전의 변화는 보지 못한다. |
| 내비 앱 운전점수 + 보험 할인 | 폰 센서로 급가속·급제동만 본다. 깜빡이·기어·길 헤맴 같은 신호가 없고, 모든 사람에게 같은 **절대 점수**를 매긴다. 가족과 연결되지 않는다. |
| 면허 반납 인센티브 | 반납이라는 마지막 단계만 다룬다. |
| 차량 기본 안전 기능 | 그 순간의 위험에 개입할 뿐, 몇 주에 걸친 변화를 추적하거나 가족에게 알리지 않는다. |

### 1.5 한 가족의 이야기 (지금)

**김정숙(72)**은 동네 병원·마트·주말 성당을 직접 운전한다. 다른 도시에 사는 **아들 김민수(45)**는 지난 명절에 동승했다가 엄마가 익숙한 성당 가는 길에서 두 번 길을 놓친 걸 봤다. "엄마, 이제 운전 그만하면 안 돼?"라고 했다가 크게 다퉜다. 그 뒤로 둘 다 운전 이야기를 꺼내지 않는다. 엄마의 운전이 정말 변한 건지, 그날만 그랬던 건지 **둘 다 모른다.**

## 2. 해결 방향

### 2.1 DriveWatch 한 줄 소개

> **DriveWatch — 부모님 운전에 차는 스마트워치.**
> **운전을 그만두게 하는 앱이 아니라, 부모님이 더 오래 안전하게 운전하게 해 주는 앱.**
> 차가 부모님 운전의 *나이*가 아니라 *변화*를 알아채고, 부모님이 스스로 정한 약속을 지키도록 돕고, 자녀에게는 감시가 아닌 안심을 준다.

### 2.2 기대 효과 한눈에

| | 지금 | 앱이 있으면 | 근거 |
| --- | --- | --- | --- |
| **조기 발견** | 사고가 첫 신호다 | **운전이 첫 신호가 된다** | 일상 운전 GPS 데이터만으로 증상 전 알츠하이머 판별 F1 0.82 (5.1) |
| **위험 운전** | 아무 피드백 없이 같은 습관 반복 | 피드백으로 **급제동 14%↓, 고위험 과속 39%↓** 수준의 행동 변화 기대 | 운전 피드백 무작위 대조 시험 (5.2) |
| **이동권** | 버티거나, 갑자기 끊거나 | 안전하게 **더 오래** 운전하고, 그만둘 때는 이동을 이어 준다 | 운전 중단 시 우울 증상 위험 **1.91배** (5.3) |
| **가족** | 근거 없는 "그만하세요" → 갈등 | 근거 카드와 대화 가이드로 **같이 결정** | 인터뷰로 검증 예정 (12절) |

### 2.3 문제별 해결

| 문제 | 해결 | 구체 장치 |
| --- | --- | --- |
| P1 변화를 모른다 | 매일의 운전을 측정해 **본인 평소 대비 변화**를 조기에 보이게 한다 | **변화 감지 엔진** (3절) |
| P2 대화가 싸움이 된다 | 결론이 아니라 **근거와 말 거는 방법**을 준다. 부모님이 먼저 보고, 자녀는 요약만 본다 | **상태별 단계 대응 + 대화 가이드** (4.3) |
| P3 선택지가 둘뿐 | "계속 vs 반납" 사이에 **부모님이 스스로 정하는 조건부 운전**을 만든다 | **운전 약속 엔진** (4.1) |

### 2.4 설계 원칙 세 가지

1. **나이가 아니라 변화를 본다.** 모든 사람에게 같은 점수를 매기지 않는다. 비교 대상은 부모님 본인의 과거 운전이다.
2. **이분법 대신 중간 지대.** 정부 조건부 면허의 자발적 버전을 먼저 만든다.
3. **판단은 사람에게, 근거는 차가.** 앱은 "운전하지 마세요"라고 말하지 않는다.

### 2.5 누가 무엇을 얻나

| 누구 | 원하는 것 | 앱에서 얻는 것 |
| --- | --- | --- |
| **부모님** (65~79세, 승용차) | 계속 운전하고 싶다, 짐이 되기 싫다 | 내 운전을 내가 먼저 확인, 스스로 정한 조건으로 운전 계속 |
| **자녀** (35~55세, 따로 산다) — **결제자** | 부모님이 안전한지, 어떻게 말을 꺼낼지 | 감시가 아닌 상태 요약, 근거 있는 대화 가이드 |
| **보험사** | 고령 계약자 손해율 관리 | 약속 이행 데이터 기반 할인 상품 (동의 시 월 이행률만) |
| **지자체·정부** | 조건부 면허·반납 정책의 실효성 | 조건 이행 기록, 반납 이후 이동 연계 |

## 3. 변화 감지 엔진

### 3.1 측정 지표

| 지표 | 정의 · 계산 | 왜 의미 있나 | 사용 API | 상태 |
| --- | --- | --- | --- | --- |
| **익숙한 길 재탐색률** | 익숙한 목적지(최근 60일 3회 이상 도착)로 가는 안내 주행에서 재탐색 횟수 ÷ 10km | 익숙한 길에서 길을 놓치는 것은 인지 변화의 초기 신호일 수 있다. 낯선 길은 제외해 오탐을 줄인다 | NaviHelper `onReRouteEnded`, `onDestinationArrived`, `getDestinationInfo` | ✅ 이벤트 존재, 수신 검증 필요 |
| **깜빡이 이행률** | 내비가 회전을 안내한 지점 100m 전 ~ 통과 사이에 해당 방향 TurnSignal이 켜진 비율 | 주의 배분·절차 기억 변화 | Vehicle TurnSignal 리스너, NaviHelper `onTBTInfo` | ✅ API 존재, TBT 필드 확인 필요 |
| **급제동 빈도** | 브레이크 ON 상태에서 감속이 초기값 0.3g(약 10.6km/h/초) 이상인 횟수 ÷ 100km | 반응 시간·차간 거리 판단 변화 | Vehicle Brake 리스너 + 속도(AAOS Car API) | ✅ API 존재 |
| **기어 머뭇거림** | 정차 중 30초 안에 기어 변경 3회 이상인 횟수 ÷ 주차 횟수 | 조작 혼동 | 기어 상태(AAOS `GEAR_SELECTION`) | ❓ 서드파티 수신 검증 필요 |
| **야간·악천후 비중** | 일몰 후 주행 시간, Wiper 작동 중 주행 시간의 비율 | 위험 노출, 약속 이행 | 시각·위치 + Vehicle Wiper·Light | ✅ API 존재 |
| **연속 운전 시간** | 한 번에 쉬지 않고 운전한 최대 시간 | 피로 노출, 약속 이행 | Vehicle Odometer trip driving time | ✅ API 존재 |
| **주행량 변화** | 주간 주행 거리·횟수 | 갑작스러운 급감도 신호(자신감 저하·건강 변화) | Vehicle Odometer | ✅ API 존재 |

임계값(0.3g, 100m, 30초 등)은 **초기값**이며 실차·사용자 데이터로 조정한다.

### 3.2 기준선

- **학습 기간**: 처음 14일 이상, 주행 10회 이상. 이 기간에는 평가하지 않는다.
- **기준선**: 이후에는 최근 8주 값을 기준선으로 계속 갱신한다.
- **같은 조건끼리 비교**: 주간/야간, 맑음/비, 익숙한 길/낯선 길을 나눠 비교한다. 비 오는 밤 운전이 맑은 낮 운전보다 서툰 건 변화가 아니다.

### 3.3 판정 규칙

| 상태 | 조건 (초기값) |
| --- | --- |
| **안정** | 모든 지표가 기준선 범위 안 |
| **관찰** | 지표 1개가 최근 2주 연속 기준선 대비 50% 이상 악화 |
| **대화 권장** | 지표 2개 이상이 동시에 악화, 또는 1개가 4주 연속 악화 |

- **표본이 부족하면 판정하지 않는다** (예: 2주간 회전 안내 20회 미만이면 깜빡이 이행률 판정 보류).
- 한 번의 나쁜 날은 상태를 바꾸지 않는다. **추세만** 본다.

### 3.4 다른 사람이 운전할 때

자녀나 배우자가 운전하면 기록이 섞인다. 시동 시 **시트 위치(Vehicle Seat 읽기)**가 평소와 크게 다르면 *"오늘은 어머니가 운전하시나요?"*라고 한 번 묻고, 아니면 그 주행은 기록에서 뺀다.

## 4. 단계별 대응

### 4.1 운전 약속 엔진 (P3 해결)

부모님이 고르고, 자녀는 **제안만** 할 수 있다. 약속을 어겨도 막지 않고, 기록하고 다음에 다시 묻는다.

| 약속 | 차가 아는 법 | 앱 행동 | 이행 판정 |
| --- | --- | --- | --- |
| 해 지면 운전 안 하기 | 현재 위치 기준 일몰 시각 + 시동 | 일몰 후 시동 시 *"오늘은 늦었네요. 꼭 가셔야 하면 천천히 가요"* 한 번 | 일몰 후 출발 횟수 |
| 고속도로 줄이기 | 내비 목적지 설정 이벤트 + 경로 정보 | 목적지 설정 시 `RouteOption.FREE`(무료도로 우선)·`COMFORTABLE` 제안 | 고속도로 주행 비중 (경로 필드 확인 필요) |
| 한 번에 1시간 넘게 운전 안 하기 | Odometer 연속 운전 시간 | 50분에 가까운 휴게소·쉼터 제안 | 60분 초과 횟수 |
| 비 오는 날은 가까운 곳만 | Wiper 작동 + 목적지 거리 | 출발 시 *"비가 와요. 오늘은 가까운 데만 가요"* | 우천 시 10km 이상 주행 횟수 |

### 4.2 매번의 운전

| 순간 | 앱 동작 |
| --- | --- |
| 출발 전 (시동, P단) | 운전자 확인(3.4), 약속과 상황 대조, 필요하면 한 문장 확인. 막지 않는다. |
| 목적지 설정 | 내비 목적지를 읽어 약속과 대조, 경로 옵션 제안. 목적지를 다시 입력할 필요 없다. |
| 주행 중 | 화면은 거의 쓰지 않는다. 익숙한 길에서 재탐색이 반복되면 *"천천히 가도 돼요. 길 다시 안내할게요."* |
| 도착 (P단) | 기록 저장, 칭찬 위주 피드백: *"오늘 깜빡이 다 잘 켜셨어요."* |

### 4.3 상태별 대응 (P2 해결)

| 상태 | 부모님에게 (차량 화면, 먼저) | 자녀에게 (폰, 요약만) | 제안 행동 |
| --- | --- | --- | --- |
| **안정** | 주간 카드: 잘한 점 2개 + 약속 이행률 | 초록 상태 + 한 줄 요약 | 없음 |
| **관찰** | *"요즘 익숙한 길에서 길 안내를 다시 받는 일이 늘었어요"* + 약속 강화 제안 | 노란 상태 + "관찰 중인 변화 1개". 세부 그래프는 부모님이 공유를 허락한 경우만 | 부모님 스스로 약속 추가 |
| **대화 권장** | 동일 안내 + *"가족과 이야기해 보실래요?"* | 주황 상태 + **근거 카드**(예: "익숙한 길 재탐색 4주 전 10km당 0.2회 → 최근 0.9회") + **대화 가이드** | 아래 목록 |

**대화 가이드** (자녀용)
- 결론 대신 질문으로 시작: *"요즘 성당 가는 길 헷갈린 적 있으셨어요?"*
- 피할 말: "나이", "위험해서", "그만"
- 함께 할 수 있는 행동: 치매안심센터 선별검사 같이 가기, 도로교통공단 교통안전교육 함께 신청, 한 번 동승 운전하기, 약속 하나 함께 추가하기

### 4.4 시작 절차

1. 자녀가 폰 앱에서 부모님을 초대한다.
2. 부모님이 차에서 **직접 동의**한다. 무엇을 기록하고 누구에게 보여 주는지 음성과 큰 글씨로 설명하고, 언제든 철회할 수 있다.
3. 부모님이 약속을 고른다(0개도 가능).
4. 14일 기준선 학습이 시작된다.

### 4.5 운전을 졸업할 때

면허 반납을 결정하면 앱이 **이동을 이어 준다**: 지자체 반납 인센티브 안내, 자주 가던 목적지(성당·병원·마트) 기반의 대체 이동 수단(DRT·택시 호출·가족 일정 공유) 연결. 현대차그룹 모빌리티 서비스로 이어지는 지점이다.

### 4.6 같은 가족의 이야기 (앱이 있을 때)

김정숙 씨는 앱을 켤 때 "해 지면 운전 안 하기"를 골랐다. 2주 학습 뒤 매주 금요일 차 화면에 *"이번 주 깜빡이 다 잘 켜셨어요. 밤 운전 0회."* 카드가 뜬다. 석 달 뒤 익숙한 성당 길에서 재탐색이 4주 연속 늘자, 엄마 화면에 먼저 안내가 뜨고 아들 폰에는 주황 상태와 근거 카드가 온다. 아들은 "그만하세요" 대신 *"엄마, 요즘 성당 가는 길 헷갈린 적 있어?"*라고 묻고, 둘은 치매안심센터 선별검사를 함께 예약한다. 결과가 정상이면 약속을 하나 더 정하고 운전을 계속한다.

## 5. 문제 해결 효과

효과는 세 갈래다. **빨리 알고(5.1), 덜 위험하게 운전하고(5.2), 그러면서도 이동을 잃지 않는다(5.3).**

### 5.1 조기 발견: 사고 전에 운전이 먼저 알려 준다 (P1)

- 미국 워싱턴대 연구팀은 인지 기능이 정상인 고령 운전자 139명의 차에 GPS 기록기를 달고 1년간 일상 운전을 기록했다. **운전 데이터만으로** 증상이 나타나기 전 단계의 알츠하이머 병리를 가진 사람을 F1 0.82로 구분했고, 나이·유전자 정보를 더하면 0.91까지 올라갔다 (Bayat et al., *Alzheimer's Research & Therapy*, 2021).
- 즉 **운전 패턴의 변화는 인지 변화의 실제 신호**다. 이 앱의 주행량 변화·익숙한 길 재탐색 같은 지표가 같은 계열이고, 우리는 GPS뿐 아니라 깜빡이·브레이크·기어 같은 **차량 신호까지** 쓴다.
- 효과 문장: *"지금은 사고가 첫 신호입니다. 이 앱은 운전이 첫 신호가 되게 합니다."*
- 한계: 연구는 진단 도구가 아니고 표본이 작다. 앱은 진단하지 않으며, 변화가 보이면 **검사를 받아 볼 계기**를 만든다.

### 5.2 행동 변화: 피드백이 위험 운전을 줄인다 (P1·P3)

| 연구 | 대상 | 결과 |
| --- | --- | --- |
| NSW 젊은 운전자 텔레매틱스 시험 (호주, 무작위 대조) | 초보 운전자 | 앱·차내 피드백 그룹의 고위험 과속 **38.9%↓**, 중간 과속 10.9%↓ (100시간당) |
| ICBC Techpilot (캐나다) | 경력 5년 미만 | 급제동 **14%↓**, 급가속 11%↓, 과속 8%↓ (대조군 대비) |

- 운전 피드백은 위험 행동을 **약 8~40%** 줄인다는 근거가 일관된다.
- 이 앱은 피드백에 **본인이 정한 약속**과 **가족**을 더한다. 스스로 한 약속과 가족의 관심이 피드백 효과를 더 키운다는 것은 우리의 가설이며 파일럿으로 검증한다.
- 한계: 위 시험은 젊은 운전자 대상이고, 사고 건수 감소는 통계적으로 확정되지 않았다. 기획서에서는 "위험 행동 감소"까지만 주장한다.

### 5.3 이동권 보호: 무작정 그만두게 하는 것도 해롭다 (P3)

- 고령자가 운전을 그만두면 **우울 증상 위험이 1.91배**로 높아지고, 신체·사회·인지 기능 저하, 요양시설 입소·사망 위험 증가와도 연관된다 (16개 연구 체계적 고찰, Chihuri et al., *Journal of the American Geriatrics Society*, 2016).
- 그래서 정답은 "빨리 반납"이 아니다. **안전한 동안은 조건을 정해 계속 운전하고, 그만둘 때는 이동을 이어 주는 것**이다. 이 앱이 반납률이 아니라 안전한 운전 기간을 목표로 하는 근거다.
- 한계: 관찰 연구라 건강 악화가 운전 중단의 원인일 수도 있다(역인과).

### 5.4 규모로 환산하면 (가정 시나리오)

- 65세 이상 사고율 4.57%(보험개발원, 2023) 기준, 앱 사용자 **1만 명**이면 연간 약 **457건**의 사고가 예상된다.
- 위험 행동 감소(5.2의 8~40%)가 사고로 일부만 이어진다고 보수적으로 가정해 사고가 **10%** 줄면, 사용자 1만 명당 연 **약 46건**의 사고를 막는다.
- 2025년 고령 운전자 사고 45,873건 전체에 같은 비율을 적용하면 연 **약 4,600건** 규모다.
- 이 수치는 **가정에 기반한 시나리오**다. 실제 효과는 파일럿으로 측정한다.

### 5.5 성공 지표 (해결됐는지 어떻게 아나)

| 문제 | 지표 | 초기 목표(가정) |
| --- | --- | --- |
| P1 변화를 모른다 | "대화 권장" 상태 발생 후 4주 안에 가족이 확인한 비율 | 70% 이상 |
| P2 대화가 싸움이 된다 | 대화 가이드 열람 후 자녀의 "이야기 나눴어요" 체크율, 부모님 만족도 설문 | 50% 이상, 갈등 응답 감소 |
| P3 선택지가 둘뿐 | 약속을 1개 이상 설정한 부모님 비율, 약속 이행률 | 60% 이상, 이행률 80% 이상 |
| 안전 | 약속 설정 후 야간·장시간 운전 비중 변화, 급제동 빈도 | 감소 추세 |
| 졸업 | 면허 반납 시 대체 이동 수단 연결 비율 | 측정 시작 |

목표 수치는 가설이다. 기획서에서는 인터뷰·파일럿 결과로 근거를 붙인다.

## 6. 존엄 설계 원칙

1. **본인 동의가 먼저**: 자녀가 몰래 켤 수 없다. 부모님 차량에서 직접 동의해야 시작되고 언제든 끌 수 있다.
2. **부모님이 먼저 본다**: 모든 리포트는 부모님 화면에 먼저.
3. **위치 추적 아님**: 자녀에게 실시간 위치·경로를 보내지 않는다. 요약과 추세만.
4. **막지 않는다**: 출발을 막거나 차량을 제어하지 않는다. 확인하고 제안할 뿐.
5. **칭찬이 기본값**: 잘한 것을 먼저 말한다. 경고는 추세가 있을 때만.
6. **말투**: 존댓말, 짧은 문장, 큰 글씨, 음성 우선.

## 8. 사업성

### 8.1 MAU 산식 (가정은 기획서 작성 시 근거로 교체)
`Pleos 탑재 차량 수 × 65세 이상 주 운전자 비율 × 앱 설치율 × 월 사용률`

- Pleos 탑재 목표: 2030년 2,000만 대(글로벌, 현대·기아·제네시스). 국내 1차 탑재는 2026-05 그랜저.
- 65세 이상 주 운전자 비율, 설치율은 **가정값**으로 시나리오 3개(보수/기준/낙관)를 제시한다.
- Retention: 부모님은 운전할 때마다 자동으로 쓰는 구조(앱을 켤 필요 없음, [fatigue-rest-direction.md](fatigue-rest-direction.md) 2.5의 내비 이벤트 방식과 동일). 자녀는 주 1회 리포트.

### 8.2 수익 모델
| 모델 | 누가 내나 | 내용 |
| --- | --- | --- |
| 가족 구독 | 자녀 | 주간 리포트, 변화 알림, 대화 가이드 |
| 보험 제휴 | 보험사 | 약속 이행·안전 운전 데이터 기반 고령자 할인 특약 (기존 내비 앱 운전점수 할인과 같은 구조, 차량 데이터라 더 정확) |
| 공공 | 지자체·정부 | 조건부 면허 시범사업의 이행 기록 수단, 반납 이후 이동 연계 |

### 8.3 확장
- 조건부 면허가 도입되면 **이행 증빙 인프라**로.
- 반납 이후 **모빌리티 서비스 연결**(DRT·호출) → 그룹 모빌리티 생태계와 연결.
- 같은 엔진으로 **초보 운전자**(기준선 성장 추적), **법인 차량 안전 관리**로 확장.

| **가족 대화** | 데이터 전달로 끝 | 근거 카드 + **대화 가이드**, 함께 할 행동 제안 |
| **운전 졸업 이후** | 다루지 않음 | 반납 후 대체 이동 수단 연결 |

기획서 문장 예시: *"일본은 2017년부터 가족이 고령 운전자를 지켜보는 서비스를 별도 단말로 제공해 왔다. DriveWatch는 같은 수요를 **추가 기기 없이 차량 자체**에서, **감시가 아닌 본인 주도**로 해결한다."*

### 9.4 사업성에 주는 시사점

- **지불 의사 근거**: ORIX는 월 2,980엔(약 2.7만원) 구독으로 판매했다. 가족 구독 가격 책정의 참고점이 된다.
- **B2G 근거**: 일본 지자체(오카야마현)가 고령 운전자 모니터링 사업에 민간 서비스를 채택했다. 국내 지자체·경찰청 시범사업 제안의 선례로 쓸 수 있다.
- **보험 연계 근거**: 일본 보험사가 블랙박스 + 가족 리포트를 보험 상품으로 판매 중이다.
- **경쟁 우위**: 단말 판매·설치가 필요한 모델보다 **획득 비용이 낮다**(차량 앱 설치만으로 시작).

## 10. 시연 시나리오 (약 2분)

1. **자녀 폰**: 엄마 초대 → 차량에서 엄마가 동의, "해 지면 운전 안 하기" 약속 선택.
2. **밤 9시 출발**(Virtual Console 시각·시동): *"오늘은 늦었네요. 꼭 가셔야 하면 천천히 가요."*
3. **주행**: 내비 안내 우회전에서 깜빡이 미사용(Virtual Console TurnSignal OFF) → 기록. 경로 재탐색 3회 → *"천천히 가도 돼요."*
4. **도착 P단**: *"안전하게 도착했어요."*
5. **주간 리포트**: 엄마 차량 화면에 먼저 → 자녀 폰에 요약과 "요즘 길 헷갈린 적 있으셨어요?" 대화 가이드.

## 11. 리스크와 확인할 것

- **감시처럼 느껴지면 실패**: 6절 원칙을 기획서 전면에. 부모님 인터뷰로 수용성 확인.
- **오탐**: 낯선 길에서 재탐색이 많은 건 정상 → 기준선을 목적지 친숙도와 함께 본다.
- **의료 주장 금지**: "치매 감지" 같은 표현 사용 금지. 변화 알림까지만.
- **개인정보**: 위치·운전 데이터는 민감 정보. 차량 로컬 처리, 요약만 전송, 보관 기간 명시.
- **경로 옵션 한계**: NaviHelper `RouteOption`에 "고속도로 회피"는 없다. `FREE`(무료도로 우선)·`COMFORTABLE`(편한 길)로 대체하고 효과는 검증 필요.
- **에뮬레이터 검증**: 기어 이벤트 수신, 백그라운드에서 Vehicle·내비 콜백, `TBTInfo`·경로 필드.
- **타깃 차종**: 1차 탑재 그랜저 운전자 중 고령층 비중은 근거 확인 필요.

## 12. 다음 단계

1. 인터뷰: 고령 운전자 부모를 둔 자녀 3명 + 고령 운전자 2명. 질문: 운전에 대해 가족끼리 어떻게 이야기하는지, 무엇이면 받아들일 수 있는지.
2. 원자료 확보: TAAS 고령 운전자 통계, 면허 보유자 수, 반납 현황.
3. 에뮬레이터 검증: TurnSignal·Brake 리스너, 기어, `onReRouteEnded`, `onTBTInfo`.
4. 화면 시안: 차량(약속 설정·출발 확인·도착·주간 리포트), 자녀 폰(요약·대화 가이드).
5. 팀 결정: 주력안(장거리 운전 플랜)과 비교해 최종 방향 확정.

## 13. 이름

**가제: DriveWatch** (영문 표기, 2026-11-05 결정)

- **이유**: 이 앱을 설명하는 가장 쉬운 비유가 "운전용 스마트워치"다. 매일 측정하고, 내 평소와 비교하고, 달라지면 알려 주고, 가족과 공유한다. 이름만 듣고 이 구조가 떠오른다.
- **주의**: 부모님 세대에게 영어 이름은 낯설 수 있다. 차량 화면의 한국어 표시명(예: "운전지킴이")을 따로 둘지는 화면 시안 단계에서 정한다.
- **확인할 것**: 같은 이름의 앱·서비스·상표가 있는지 앱 마켓과 특허청 상표 검색(KIPRIS)에서 확인.

검토한 후보

| 후보 | 결과 | 이유 |
| --- | --- | --- |
| DriveWatch | **채택(가제)** | 스마트워치 비유가 바로 전달됨 |
| 운전안부 | 보류 | 가족이 챙긴다는 톤은 좋지만 너무 함축적이라 기능이 바로 안 보임 |
| 오래운전 | 보류 | 목표(안전하게 더 오래)는 담지만 가족·변화 감지가 안 보임 |
| 운전주치의 | 제외 | 구조는 정확하지만 촌스럽고, 진단으로 오해될 수 있음 |
| 운전지킴이 | 보조 후보 | 부모님 세대에 익숙. 차량 화면 한국어 표시명 후보 |
| 함께핸들, 늘운전 | 제외 | 공동 운전으로 오해되거나 기능이 안 보임 |
